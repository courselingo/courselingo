# 视觉复核管线（本项目的第二道人工闸门）

这四个脚本原来只存在于工作区根目录，**不在任何 git 仓库里** ——
而它们是「配图视觉复核」这道闸门的**全部实现**。
⇒ 一旦丢失，这道闸门的方法就没有了。所以在此留档。

## 文件

| 文件 | 作用 |
| --- | --- |
| `refresh_one.py` | 入口。用法：`python refresh_one.py <课程名>`。重栅格化 → 找出**过期报告**（报告记的哈希 ≠ 当前文件哈希）→ 并发送模型复核 → 写报告 |
| `visual_review.py` | 全量版本 + **提示词**（`PROMPT` / `prompt_for(viewbox)`）+ 判定解析 |
| `vision.py` | 模型调用（`read_key` / `read_base_url` / `call`） |
| `rasterize.py` | SVG → PNG 栅格化 |

## 报告落在哪

```
preview/visual-review/<课程>__<图名>.md
⇒ 必须再复制进 courses/<课程>/docs/audit/visual-review/
  （`check_reviewed.py` 只认仓内那一份）
```

## 判定行

模型最后一行写 `判定：可用` / `判定：需小修` / `判定：有错误` 三者之一。
解析在 `read_verdict`，**会先剥掉 Markdown 标记**再匹配 ——
因为提示词早期把判定写成反引号包裹，模型就常回成加粗体 `**判定**：可用`，
而字符序列 `* * 判 定 * * ：` 里 `判定：` 并不连续 ⇒ 匹配不上 ⇒ 取到 `"?"` ⇒
**`check_reviewed.py` 的 `if v in ("有错误","需小修")` 对 `"?"` 为假 ⇒ 静默放行。**

## ★ 两个已修的坑（都写进代码注释了）

1. **版本戳必须用「行尾归一化后」的哈希**（`.replace(b"\r\n", b"\n")`）。
   否则同内容在 CRLF 工作区与 LF 检出里得到不同哈希，报告永远与它描述的图对不上。
   **根因是同一段逻辑在两个文件里各写一遍**（`visual_review.py` 与 `refresh_one.py`），
   而我先补的那一份不是管线在跑的那一份 ⇒ `附录十四` 的教科书形态。

2. **提示词必须带上该图的 `viewBox`，并要求坐标落在范围内**（2026-09-29 补）。
   起因：一次复核给出 **4 条几何主张，作者逐条量测后全部不成立**：
   ```
   「中部两框不等宽 707 vs 622」 → 实测两框都是 344
   「标题偏右 40–50px」          → 渲染后量墨迹：中心 379.5 对画布 380.0
   「右端标签右缘距画布仅 2–3px」→ text-anchor="end" x="738" ⇒ 右边距 22px
   「第四框明显窄 / 整排偏左」   → 四框都是 160，间隙 25/25/25
   ```
   **根因是坐标系**：它报的数常常**超出那张图 viewBox 的宽度本身**
   （有一张 viewBox 只有 707，而它报 782 / 716）。
   ⇒ 现在把 `viewBox` 写进提示，**给它一个能自查的边界**。

## 而它的**文字类**结论是可信的

同日实测：同一批复核里，文字类结论（`desc` 写反、图内文字与标题相反、
「15% 是什么的 15%」没有落点）**全部成立**，而且有两条是**别的闸门独立也发现的**。
⇒ 所以口径是：**文字类可信，几何类必须自己量**（`附录十一`）。
