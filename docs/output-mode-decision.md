# 产出形态的决定 · 「翻译」还是「讲解」

> 记录人：CourseLingo Lead ｜ 日期：2026-09-29
> 起因：用户目标「继续，至少全量翻译完 4 门课程。」
> 本文回答一件四个作者都会问到的事：**每讲到底产出什么？**

## 1. 先把两个词在本项目里的含义钉死

| 词 | 对应字段 | 本项目定义（逐字引自 `content-policy.md`） |
| --- | --- | --- |
| **讲解** | `output_mode = "explanation"` | 「我们自己写的讲解，不是别人课程的复制品」；「自己写一篇讲解同样概念的原创文章，风险最低」 |
| **翻译** | `output_mode = "transcript"` | 「**翻译完整逐字稿**」；「属于**衍生作品**，它复制了**原作的全部表达** —— 风险完全取决于原课程的实际许可条款」 |

**⇒ 所以在本项目里，「翻译」是一个**法律含义很重**的词：它指的是**复制原作全部表达**的衍生作品。**
**⇒ 而 `content-policy.md` 明写：「产品的默认形态：**讲解为主，翻译为辅**。」**

## 2. 用户这次说的是「翻译」，而约束是别的

用户目标逐字：**「继续，至少全量翻译完 4 门课程。」**

**而同时成立的还有用户此前给的内容方针（逐字）**：
> 「重点是要**易懂易学**……让**基础不好的初学者**也较能接受。**需要减少 AI 味的表达**。」

**⇒ 这两条有张力**：
- **逐字译**（transcript）会**保留原讲义的表达与节奏** —— 而讲义是给课堂上的人看的，**不是给基础不好的自学者看的**；
- 「易懂易学 + 初学者 + 少 AI 味」要求的是**重述**，而不是**搬运**。

## 3. 决定

**⇒ 每讲产出 = 「紧贴原文结构的中文讲解」，`output_mode = "explanation"`。**

具体形态（四个作者照此办理）：

| 要素 | 要求 |
| --- | --- |
| **结构** | **跟随源讲次的推进顺序**（哪一节先讲什么，就按那个顺序）—— 这一点让产出**可对照原文**，也就承担了「翻译」的可验证性 |
| **术语** | 每个术语**首次出现给中英对照**，之后用中文；术语取自 `glossary.toml` |
| **难句/关键定义** | **给出原文短引 + 中文**（一两句，不是整段）—— 精度要求高的地方必须能回到原文 |
| **其余** | **用易懂中文重述**，讲清「为什么」与「不这样会怎样」 |
| **不做的** | **不产出逐字全译**；**不做双语并排全文**（那走同一道闸门，见 `content-policy.md` 第 110 行） |
| **配图** | **自绘 SVG，不转载原图**（房规硬要求） |

## 4. 为什么这样定（四条理由，可复核）

1. **用户的风格方针**是硬约束，而逐字译与它冲突（见 §2）；
2. **项目自己的政策**是「讲解为主，翻译为辅」（`content-policy.md` L15）；
3. **规模**：四门全量约 **100 讲**（31 + 21 + ~24 + ~25）。**逐字译 + 讲解两遍 = 200 讲的工作量**，
   在本目标的轮次预算内不可行 —— **必须二选一**；
4. **法律边际**：讲解是「不复制对方表达」的最低风险形态；逐字译把风险完全绑在上游许可上。
   **上游许可已双签**（见 `full-translation-scope.md` §3），**所以逐字译是被允许的 —— 但它不是必需的**。

## 5. 而**授权允许逐字译**这件事，仍然要如实记录

**⇒ 四门课的 `transcript` 现在都是**解锁**状态**（第二人复核已签字）。
**⇒ 本文只是**选择了不做**，不是**不能做**。**

**⇒ 若用户明确要逐字译**（例如「我要能对着英文原文读」），**改 `output_mode` 即可，无需重新核实授权** ——
**唯一还要补的是：该讲**实际依据的那份材料**单独取证一次**（逐页原则，见 §6）。

## 6. 无论选哪种形态，两条义务都不变

1. **逐页取证**：把某讲改为 `transcript` 之前，**该讲依据的那份材料页要单独抓一次** ——
   OCW 的许可是逐页复制的，ETH 是逐页页脚，CS168 是教材根页 + 具体章节页；
2. **两道人工闸门 + 五道机检**：非作者事实核对、配图视觉复核，加 `validate` / `check_style` /
   `audit_content --strict` / `check_figures --strict` / `build_site`，以及提级前的 `check_reviewed`。

## 7. 一句话给四个作者

> **按源讲次的结构写中文讲解，术语给中英对照，难句给原文短引；
> 不逐字全译，不转载原图。**

## 8. 补记（第二轮）：逐字稿能不能拿到，**要逐讲实测** —— 而不是按课程一刀切

> ### ⚠️ 本节已被**同一位作者**自我更正（第三轮），更正内容见下，原结论的范围太大。
> **更正后**：判据是「**该 PDF 的文本层是否自洽**」，而这是一件**逐文件**的事。
> 第 1 讲的文本层确实是碎的；**第 2 讲的文本层完好**，只是**之前那个抽取脚本用错了**。
> **⇒ 原文见本节末尾「自我更正」小节。**

### 8.0 原始结论（**已按 8.1 更正**，保留以便追溯）

**四条理由之外，还有第五条，而它是独立的一条（不是「不划算」，是「做不到」）：**

**CMU 15-442 的课件是**图片型 PDF**，文本层不可用。** 实测：

```
_sources/mlsys-15442/text-clean/mlsys-slide-01-course-introduction.txt
  201,157 字符 —— 但内容形如：
    「AutomatedApproachestoAccelerateMachineLearningZhihaoJia|StanfordUniversity」
    「15 - 442 / 15 - 642 Mac hi ne Lea rn i ng Systems Sp ri ng2026」
                      ↑「Machine」被切成「Mac hi ne」，「Learning」被切成「Lea rn i ng」
    ⇒ 词内被切碎、词间无空格
```

**对照参照**（`_sources/MIT6_006F11_lec01.pdf.clean.txt`，文本层正常）：
```
  「Lecture 1 / Introduction and Peak Finding / 6.006 / Fall 2011 / Lecture 1: …」
  ⇒ 词完整、有空格、可直接检索
```

**⇒ 所以对这门课而言，即便把 `output_mode` 改成 `transcript`，也**没有可靠的逐字底稿可用** ——
只能先人工回译，而回译出来的东西**不是**「复制原作的全部表达」，**法律上也就不再是那个 `transcript` 了**。**

**⇒ 结论**：`transcript` 对 CMU 15-442 **工程上不可行**；这不是授权问题，是**源材料形态**问题。
**⇒ 而它对其它几门课是否成立，要各自验一次**（6.006 的文本层是好的；ETH 与 cs168 未验）。



### 8.1 自我更正（第三轮，`mlsys-author` 自己推翻了上一条的适用范围）

**原文**（上节）主张：「CMU 15-442 的课件是图片型 PDF ⇒ 文本层不可用 ⇒ `transcript` 工程上不可行。」

**作者随后发现**：`_sources/_audit/pdftext3.py`（团队共享目录里已有的脚本）**能按 PDF 内嵌的 ToUnicode CMap 还原文本**。
实测对比：

| 文件 | 之前用的 `text-clean/*.txt` | `pdftext3.py` 的 `.faithful.txt` |
| --- | --- | --- |
| 第 1 讲 | 词内切碎、词间无空格 | **同样碎片**（该 PDF 的文本层本身就这样） |
| **第 2 讲** | 855 行里只有 1 行是真英文 | **33 页全部可读**，含完整句子 |

**Lead 独立复核**（我自己跑了一遍，不看它的说法）：
```
mlsys-slide-02-introduction-to-MLSys.pdf.faithful.txt   18,682 B / 1,134 个英文词
  「Automated Approaches to Accelerate Machine Learning / Zhihao Jia | Stanford University /
    15 - 442/15 - 642: Machine Learning Systems / Introduction to Machine Learning Systems」
  ⇒ 词完整、有空格 ✅
```
**⇒ 更正成立。**

**⇒ 所以正确的判据是**逐文件**的：**

> **「这份 PDF 的文本层是否自洽」—— 而测法就是 `pdftext3.py` 生成的 `.faithful.txt` 能不能读出成句的英文。**

**⇒ 而作者给出的行动建议我采纳**：把 `pdftext3.py` 对全部缓存 PDF 跑一遍，
**逐讲记录「有无可用文本层」**，再决定每讲的取材方式。

### 8.2 为什么这条更正比原来的结论更有价值

**原来的结论是**关于整门课**的（「这门课不行」）；更正后是关于**单个文件**的（「这个文件不行」）。**
**⇒ 而原来的证据只是**第 1 讲一个文件** —— 从「一个文件」推到「一门课」，正是 `附录十四`
（结论的适用范围，比它引用的证据范围大）的**教科书式复发**。**

**⇒ 而这次抓住它的不是别人，是**提出原结论的人自己**。
⇒ 它写的是：「**我改口了，因为新证据推翻了旧结论的适用范围**」——**
**⇒ 「适用范围」这四个字正是 `附录十四` 的原文用词。**
