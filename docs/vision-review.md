# 配图视觉复核 · Visual Review

> **这份文件要解决的问题**：本项目有 102 张手绘配图，在很长一段时间里
> **没有任何人、任何模型真正看过它们**。房规 linter 只能证明几何没毛病，
> 事实核对比对的「页面 vs 源」，内容审计只数图够不够。
> **「这张图画得对不对、读者一眼能不能看懂」没有任何闸门在管。**

## 1. 为什么必须单独设一道

2026-09-28 第一次真正跑视觉复核，前 77 张就查出 **12 张「有错误」+ 29 张「需小修」**。
这些图**全部通过了房规 linter**（0 error 0 warning）。查出的缺陷分成四类，
**没有一类能被既有闸门捕捉**：

| 类别 | 实例 |
| --- | --- |
| **标题承诺的结构不在图里** | 框子标题写「三条边互相拉扯」，框内只有三张**彼此分离**的卡片，**没有任何边**；另一框标题写「一致性**刻度**上的选点」，框内**没有刻度线也没有轴** |
| **技术性错误（会误导人）** | 把「多数派定案 / Raft 与 Paxos」画在 linearizability 与 eventual consistency **之间**，等于宣称 Raft/Paxos 的一致性**弱于** linearizability —— 而多数派共识提供的正是 linearizable 保证 |
| **箭头拓扑与框内文字冲突** | 把「两样都做不到」画成两个重试分支的**必经后续**，而框内写的是「两者都不行时」才到那里 |
| **标题与图内流程对不上** | 标题写「**一次**比较的分叉」，图内流程却需要比较左右各一次；两个分支**不互斥**（局部谷时同时成立）且未标 if/else 顺序，**分叉不唯一** |

还有一类只能靠视觉发现：**图内部数字口径矛盾**。
GFS 那张讲光速延迟的图，横轴区间画的是**单程**（消息发出→到达），
而数字取的是**往返**量级 —— 关键的是，**作者忠实照抄了源的数**
（源自己 `3e9 × 0.0275 = 8.25e7`，却写成 8.4e7），所以「归属」这关是过的。
**「忠实于源」不等于「图内部自洽」—— 这是两道不同的检查。**

## 2. 怎么跑

三件工具放在工作区根目录（它们要读本机的 DSH 凭据与配置，所以不入平台仓库）：

| 脚本 | 作用 |
| --- | --- |
| `rasterize.py` | 把 `courses/*/content/**/figures/*.svg` 栅格化成 2× PNG 到 `preview/png/`（Chrome headless）。**read_image 与视觉 API 都只吃位图，SVG 必须先渲染。** |
| `vision.py` | 直接调用 OpenAI 兼容网关读图（见 §4）。 |
| `visual_review.py` | 批量复核：每张图交给视觉模型，输出「版面 / 全部文字 / 缺陷 / 判定」四节，落盘到 `preview/visual-review/`。 |

```bash
python rasterize.py                 # 全部课程；也可传具体课程目录
python visual_review.py             # 批量复核，判定写入每个 .md 的末行
```

**判定只有三种**：`可用` / `需小修` / `有错误`。汇总看 `preview/visual-review/_summary.json`。

### ★ 一个踩过的坑：输出名必须带课程前缀

第一版用文件名做键，结果 **102 张只生成 96 个 PNG** ——
因为 **cs168 与 mit-6.5840 都有 `intro-1..intro-9`**，6 组重名互相覆盖。
**如果不查这个数，复核会把别的课程的图当成这一张来判，然后把错的结论当证据。**
现在输出名是 `课程__文件名.png`。**数量不对就是有 bug，不要往下走。**

## 3. 复核提示词的要求

给视觉模型的提示词必须要求四节，且**必须要求它照抄图内全部文字**：

- **版面** —— 几行几列、箭头走向
- **全部文字** —— 逐一照抄（不翻译、不概括、不漏）
- **缺陷** —— 每条注明**具体是哪个标签/哪个位置**；并明确「**没有就说未发现，不要为了凑数编造**」
- **判定** —— 末行三选一

要求照抄全部文字，是因为**排版缺陷只有在拿到全文之后才能核对**
（文字漏了、重复了、与正文不一致，都要靠这一步暴露）。

## 4. 为什么是「直接调网关」而不是 `read_image`

`read_image` 报：

```
model "X" does not declare image input; switch to an image-capable model
```

根因在 `~/.dsh/settings.yaml.imported`：provider 里这些模型**只声明了
`contextWindow` / `maxTokens`，没有任何图像能力字段**。所以这是
**harness 侧的声明缺口**，不是模型不支持 —— `read_image` 在处理声明时
就拒绝了，根本不去尝试。

而 provider 是 `api: openai-completions`、baseURL 是 OpenAI 兼容网关，
所以 `vision.py` 按 vision 格式直接 POST 即可，**实测 `qwen3.8-max` 直接收图**。

> 正式的图像通路是插件 **`@anionex/dsh-vision-toolkit`**（web profile 的 bundles
> 里已装），需要在 **设置 → 视觉工具** 里配置视觉模型后会注册
> `<模型名> (Vision Toolkit)` 变体。`vision.py` 是不依赖该配置的直连方案。

## 5. 与其它闸门的分工

| 闸门 | 管什么 | 为什么不够 |
| --- | --- | --- |
| `check_figures.py` | 几何、间距、溢出、XML 转义 | 上表四类缺陷它**全部判为通过** |
| `audit_content.py` | 每节几张、缺口、图文咬合 | 只数「有没有图」 |
| 事实核对（读 SVG 文本） | 页面断言 vs 源 | 比对的是**源**，不是**图内部自洽** |
| **本文件（看渲染图）** | **图讲得对不对、自不自洽、看不看得懂** | —— |

## 6. 流程位置

**每张图定稿前都要过；配图改动后必须重跑受影响的那几张。**
它和「陌生读者测试」「独立事实核对」一样，属于**人工闸门**，不是机检 ——
`draft → reviewed` 的前置条件。
