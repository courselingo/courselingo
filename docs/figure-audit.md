# 配图审计 · Figure Audit

> **这份文件要解决的问题**：把「三张图」当成配额。
> 第一次派子代理写配图时，指令写的是「每篇 ≥3 幅」，结果**每一篇都恰好只有 3 幅** ——
> 一个需要图的机制段落旁边空空如也，而配额已经交差。
> 图不是配额，是**内容的函数**：讲到需要图的地方就得有图。

## 1. 两条规则，主次分明

| | 规则 | 性质 |
| --- | --- | --- |
| **主** | **必要性**：每个二级小节都要回答「这块需要图吗」；需要就必须有 | 判断，由审计人负责 |
| **辅** | **密度**：每千汉字 ≥2 幅（目标 3，上限 5） | 兜底，由 `audit_content.py` 机检 |

密度只是**用来抓「该画没画」**的网。真正决定该有几张图的是内容本身。
反过来，密度也是上限：**超过每千字 5 幅就该怀疑是在凑数**。

## 2. 必要性怎么判

对**每一个二级小节**（`## …`）问这五个问题，命中任一即「**必须配图**」：

| # | 这一节在讲… | 例 |
| --- | --- | --- |
| 1 | **结构**：谁连谁、谁在哪一层 | GFS 单主节点 + 块服务器；ZooKeeper 数据树 |
| 2 | **流程**：先做什么、后做什么 | 一次 RPC 的调用链；GFS 写入的七步 |
| 3 | **状态变化**：什么条件下从 A 变成 B | Raft 三种角色的转换；watch 触发后失效 |
| 4 | **取舍/对比**：两个方案各付出什么 | 链式分发 vs 树形分发；三种投递语义 |
| 5 | **失败**：哪里会坏、坏了看到什么 | RPC 超时后的四种歧义；多数派相交 |

明确**不需要**图的小节（可以不配，但要在审计记录里写一句理由）：

- 纯**定义/术语**澄清（一句话能说清，图反而增加负担）
- 纯**历史/背景**叙述
- **清单/对照表**（表格比图清楚）
- `读完应该能回答`、`脉络回顾`、`溯源` 这类收尾小节

## 3. 一幅图必须能回答

> **「没有它，读者会在哪一句卡住？」**

答不出来 = 这张图不该存在。三种典型反模式：

| 反模式 | 表现 |
| --- | --- |
| **装饰图** | 画了一个「分布式系统」云朵，但不承载任何信息 |
| **把文字搬进图** | 图里就是一整段文字，删掉图读正文更清楚 |
| **凑数图** | 为了达成密度硬塞，与本节论点无关 |

## 4. 图必须与正文咬合

- **引出句**：图前一句说明「接下来这张图讲什么」
- **解读句**：图后一句说明「所以这张图说明了什么」
- **`alt` 承载信息**（≤60 字），能替代图片传达结论，不写「示意图」
- 机检：[`audit_content.py`](../template/scripts/audit_content.py) 会检查图前后是否有正文（`[图无引出]` / `[图无解读]`）

## 5. 密度阈值（`audit_content.py` 实装）

> **★ 决定密度的是「每节几张」，不是「每千字几张」。**
> 第一轮我们按「每千字 3 张」派工，结果每节平均 **3.02 张**、
> 22 个小节 ≥3 张，最极端的两节各 **11 张**（Paxos 的两个阶段、Raft 的工作流程）。
> 而图文重复度全在 **0.64 以下** —— 图**不是**在复述正文，
> 是**同一个机制被切得太碎**。所以约束必须落在「节」上。

### 主约束 · 每节张数

| 项 | 值 | 级别 |
| --- | --- | --- |
| 每个内容小节 | **≥1 张** | **ERROR** |
| `MAX_GAP_CJK` | 连续 **1200** 汉字之内必须有一张图 | **ERROR** |
| 单节最大同版式组 / 该节图数 | **≤ 1/3** | ERROR |
| `MAX_FIG_PER_SECTION` | 2（>1500 汉字放宽到 3） | **参考，不再作为硬上限** |

> **★ 2026-09-28 修正：「每节 ≤2/3 张」从上限降级为参考。**
>
> 它当初是拿来防「每节堆四五张碎图」的（第一轮每节平均 3.02 张、最极端两节各 11 张）。
> **那个目的现在由 `MAX_GAP_CJK` 与「版式多样性 ≤1/3」承担**，而固定张数上限
> 在多了一轮校对之后开始**惩罚正确性**：
>
> GFS 那一页的三节余量只剩 **34–39 个汉字**（gap 1166/1163/1161 对上限 1200）。
> 而它变长的原因是**好的变长** —— 加的是归属标注、源文依据、边界条件、易错点。
> 作者为把 §七 从 1205 压回 1200，**删掉了一句源文内容**
> （「论文把原因归给当时的网络栈与流水线配合得不好」）。
>
> **内容越诚实就越长，而固定上限不跟着长 —— 于是「越诚实越容易顶穿闸门」。**
> 那是规则在惩罚正确性，方向错了。
>
> **新判据只有两条，都是读者视角的**：
> 1. **任何连续 1200 汉字之内必须有一张图**；
> 2. **版式不得单调**（单节最大同版式组 / 图数 ≤ 1/3）。
>
> 也就是说：**一张图够就不加；有 1600 字没图就补一张真讲机制的图。**
>
> **这比原规则更严，不是更松**：原规则允许你在一节里堆 3 张图、然后 1400 字没有图
> （因为它只看张数）；新规则不允许。
>
> **默认仍是一节一张。** 只有该节确实讲了**两个独立机制**时才给第二张。
> 一个机制画三张以上就是把读者切晕 —— 应当**合并**成一张，
> 用版面（链／分叉／时间轴）承载时序，而不是拆成多张各画一步。
>
> **小节太长时，优先拆小节，而不是加图。** 拆节同时降低 gap、降低单节图数、也更好读。
> **只有当「这一节是在讲一件事、而那件事确实需要第 4 张图」时才加图** ——
> 不是为了凑 gap 而加。

### ★ 补图要补在窗口**内部靠前**，补在尾部等于没补

实测踩到（`mit-6.5840` 作者，2026-09-28）：它按新判据给两个逼近上限的窗口各补一张图，
**第一版放在窗口尾部**（即原本紧挨着下一张图的位置）——
**最大无图段反而从 1166 涨到 1186。**

原因：**无图段是从「上一张图」量到「下一张图」的。**
把新图放在窗口末端，只把最后那一小截切出去，**前面那上千字仍然连在一起**；
而新图的引出句还额外添了 23 字。

移到窗口**前部**（"先算一笔具体的账" 之后、"不变量陈述" 之后）之后：
**最大段 1166 → 1010**，其余 968 / 962 / 816。

> **规则**：补图时先找出那个最长无图段的**起点**，把图放在起点之后不远处。
> 放在段的末端只是把段切成「很长 + 极短」两截，长的那截照样超限。
>
> **执行者极易踩这个坑**，因为它直觉上会「在缺图的地方补一张」——
> 而「缺图的地方」恰恰是段的末尾（再往后就是下一张图了）。

### ★ 次序：先问「这是不是两件事」，再考虑补图

**把「补图」当第一选择、把「拆节」当第二选择，是错的次序。**
若那一节本来就该是两件事，**拆节才是对的解**；
补图只是把两个话题硬缝在一节里，gap 降下来了，**结构问题还在**。


### 辅约束 · 密度带

| 项 | 值 | 级别 |
| --- | --- | --- |
| `MIN_FIG_PER_K` | **1.2** | ERROR（很低的红线，只抓「几乎没图」） |
| `TARGET_FIG_PER_K` | 1.8 | **仅参考输出，不作闸门** |
| `MAX_FIG_PER_K` | **2.8** | WARN（超过就是幻灯片）→ `--strict` 下致命 |
| `MAX_GAP_CJK` | 1200 汉字 | ERROR（中间不能有太长的无图段） |

> **★ 为什么密度下限不是闸门**
> 我们一度把「未达 1.8」也设为 WARN，CI 用 `--strict` 就等于致命。
> 结果它和「每节 ≤2」直接打架：mapreduce（5 节 / 6,981 字）按每节上限
> 最多 12 张，而 1.8 的下限要求 12.6 张 —— **数学上无解**；
> raft（5 节 / 7,839 字）同样（12 < 14.1）。
>
> 根因是**冗余约束**：用户抱怨的失败模式是「图太多」，所以上限必须硬；
> 而「图太少」已经被**每个内容小节 ≥1 张**覆盖了。再把密度下限设成闸门
> 就是多此一举，而且在小节少而长的页面上必然与上限冲突。
>
> **度量互相矛盾时，删掉冗余的那一条，而不是让执行者去凑数。**
> 这条经验适用于所有闸门设计：**互相矛盾的约束会逼出做假，而不是逼出质量。**

### ★ 这两个数字是怎么定下来的（供后续课程照抄）

本课程平均每个内容小节约 960 汉字。「每节 1–2 张」换算过来正好是
**每千字 1.0–2.1 张**，所以目标定在 **1.8**。

**为什么不再用 3.0**：那是第一轮拍的数。实测下来
一篇 9,000 字的讲义会要 27 张图，读者每 330 字就撞见一张图，
**图解不再是帮助，而变成负担**。密度应当由「有几个值得画的机制」决定，
而一个二级小节通常只有**一个**。

## 6. 审计流程

```bash
# 1. 机检：先看硬缺口在哪
python scripts/audit_content.py --root .

# 2. 人/agent 审计：逐个小节判必要性（见 §2 的五个问题）
#    产出「配图审计记录」（见 §7）

# 3. 补图：按记录里判为「必须配图」的位置补。**该节已有 2 张还嫌不够时，
#    先想「能不能合并成一张」，而不是加第三张。**
#    每补一张都要过房规：python scripts/check_figures.py --root . --strict

# 4. 复检：密度、分布、咬合三项都应转绿
python scripts/audit_content.py --root . --strict
```

**什么时候做**：每篇内容**定稿前必须做一次**；`status` 从 `draft` 提到 `reviewed` 的前置条件之一。

审计要留痕，否则无法复核。建议追加到页面所在仓库的 `docs/audit/<page>.md`：

## 附录 · 版式多样性必须看**单节分布**，不能只看全局最大组

### 这条是怎么来的

`fig-pruner` 曾报「最大同版式组 **8/85 = 9%**」，我据此认为版式重复已经解决。
2026-09-28 一次独立事实核对指出：**GFS 一节 16 张图里 12 张「只有文字不同」**
（描述为「上 3 框 / 下 3 框、209×68、x=38/275/512、同一 y」）。

我按**精确几何指纹**（把每张图所有 `<rect>` 的 x/y/w/h 归一化成 viewBox 比例后排序）
自己复算，结论是：

| 章节 | 图数 | 最大同版式组 |
| --- | --- | --- |
| 01-introduction | 11 | 2 |
| 02-rpc-and-threads | 13 | 2 |
| **03-gfs** | **16** | **5**（另有 3 张同组 → **8/16 几何完全相同**） |
| 04-paxos | 9 | 1 |
| 09-zookeeper | 14 | 1 |

**两个数字都是真的，而且不矛盾。** 全局 8/85 ≈ 9% 掩盖了一节里一半的图长得一样。
**读者体验的不是全局比例，是连着翻到五张同构图的感受。**

### 因此定的规则

> **版式多样性按「单节内最大同版式组 / 该节图数」衡量，阈值 1/3。**
> 超过就返工，与全局比例无关。

按这条，GFS 的 8/16 = **50%** 远超阈值，必须重排；其余各节约 1/14–2/13 = **7%–15%**，通过。

### 复算方法（可复用）

取每张 SVG 的 `viewBox` 与全部 `<rect>`（排除画布本身），
按 `round(x/W, 2), round(y/H, 2), round(w/W, 2), round(h/H, 2)` 归一化后排序拼接成指纹，
同一指纹即几何完全同构。**归一化是必需的** —— 否则两个画布尺寸不同的图会被当成不同的版式。

### 一个附带教训

我此前接受「9%」时，**只核了被报告的那个聚合数字，没有核它的分解**。
**聚合指标通过不等于每一层都通过。** 这条与 `quality-audit.md` 附录二里
「归属标签要与命题真假分开查」是同一类毛病：**看了一个维度就宣布结论。**


### ★ 度量口径：`alt` **计入**汉字数，但**不计入**句子

`cs168-author` 实测（2026-09-28）：它只改了 `intro-5` 的 `alt`，正文汉字
**5051 → 5062（+11）**，与 alt 增删的 11 字逐字吻合。读源码确认：

```python
body  = strip_fm(raw)                          # 未剥图片语法
n_cjk = len(CJK.findall(body))                 # ⇒ alt 计入汉字数 → 影响密度与尾部缺口
sentences(): re.sub(r"!\[[^\]]*\]\([^)]*\)")  # ⇒ 但句子切分先剥掉整条图片语法
```

⇒ **`alt` 计入「汉字数」，不计入「句子」。**

**这条有两个直接后果，而且方向相反：**

| 想做的事 | alt 有没有用 |
| --- | --- |
| 躲开**尾部无图缺口**（1200 汉字上限） | ❌ **没用** —— 在尾部写 alt，一样顶缺口 |
| 降低**最长句**（120 汉字上限） | ✅ **有用** —— 长解释移进 alt 就不再算作句子 |

**我（Lead）曾告诉执行者「解释放进 alt，alt 不计入正文汉字」—— 那是错的，而且建议是反的。**
若它照做，会**以为躲开了缺口、实际没有**。**已更正。**

> 记一条：**「我以为的度量口径」和「脚本实际的口径」是两件事。**
> 这与附录七同源（判据本身也是参照），但更具体 ——
> **它是「度量里到底算进了什么」**。要断言某条约束会不会被触发，
> **先读脚本里那几行 `findall`，别看名字猜。**


### ★ 必查项：「图单独拿给读者，他会读出什么？」

`quality-audit.md` **附录十** 把这一类立成了单独一条。**本节的配图复核必须加这四问**：

1. **归属**：每个标签/文字仅凭位置能否唯一确定属于哪个元素？（等距夹在两者之间 ⇒ 缺陷）
2. **视觉语言**：几何形式（实线/虚线/颜色/对齐）暗示的关系，与文字说的是不是同一件事？
3. **对齐**：两排元素**对齐**是否暗示了**一一对应**？若不是，必须显式断开。
4. **两端相接**：连线/箭头端点要不要碰到它连接的框？（悬空 ⇒ 只能推断）

**理由**：这一类的四张图**几何都画对了**，错在**图与文字之间** ——
**两样各自都对，合起来能被读成第三样**，而**初学者最依赖视觉结构、也最没有能力发现对不上**。
