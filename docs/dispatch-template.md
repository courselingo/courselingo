## 一、不管派给谁，这三段必须原样带上

### ① 字段先核（因为我在派单里写错过很多次）

```
★ 落盘前**自己核一遍编号 / slug / URL / 标题**：读 `docs/lecture-manifest.md` 里对应的那一行，
  并抓源页面看 `<title>`/H1，两处对照。
★★ 我给的字段错过很多次（URL 是另一门课的版本 / 编号与 URL 差一节 / 文件名有无连字符 /
   我写的「未定义术语」清单在几分钟内就被并行的流加上了）。
   ⇒ **来源与你核到的不一致时，以来源为准，并报我。**
   ⇒ **我给的具体缺口也可能过期 —— 先自己重跑那个判据（`附录七十`）。**
★ 落盘前 `ls content/` 确认目录未被占用。
```

### ② 末尾三段（**这一段是这次新增的**）

```
**每一讲末尾必须有三段**，按此顺序：
  1. `## 读完应该能回答`（**8 条以内** —— 10 条会触发 check_style 的「段落过长」）
  2. `## 脉络回顾`
  3. `## 溯源`

★ 而 `## 脉络回顾` 是**我在多数派单里漏掉的那一段**（`附录六十三`）：
  · 它的作用是**把这一讲接回主线**（给初学者一条线）
  · 而 cs168 有 21 讲缺它、mlsys 有 21 讲缺它、eth-ca 有 16 讲缺它 —— 而 mit-6.006 **全齐**
    （因为只有那门课的派单里写过它）
  · ⇒ **所以它缺与不缺，取决于派单里写没写，而不是作者做不做得到。**
★ 而三段顺序也重要：`audit_content` 把这三节当**收尾元信息**（不要求配图）。
```

**★★ 而第一段的约束是「问号 ≤4」，不是「几条」**（2026-09-29 修，`附录七十九`）：
```
· `check_style` 的 `[设问]` 判据数的是**全页问号**（阈值 **4**）
· 而 `[脉络]` 判据又要求**收尾小节 ≥100 汉字**
⇒ 所以：
  · 每条都写成**问句** ⇒ 问号数 = 条数 ⇒ **≤4 条**
  · 写成**陈述式要点**（「X 是 Y」，不带问号）⇒ **条数不限**
    ★ 实例：一位作者写了 **8 条陈述式要点**（全页问号 1，而那个 1 在溯源的英文引句里）⇒ 通过
★ 而**我自己犯过一次**：我把「每条都是问句时 4 条正好」当成了「判据要求 4 条」，
  并在四封派单里那么写了 —— 而那是**把一个特定情形当成了那个类**（`附录七十九`）。
```

### ③ 图：差集两个方向 + 位置

```
★★ **图文件与引用的差集，两个方向都要报**（孤儿图 / 缺文件）。
   ⇒ 而 `check_figures` 现在有一条**硬错误**管「引用了而磁盘上不存在」，
     它同一天就救了一位作者一次（他按 11 节写 11 张引用却生成 12 张，差集报出孤儿）。
★ **图放在小节的倒数第二段之后**；更稳的做法：
  **先写小节的收尾段，再把图插到它前面** ⇒ 「图后面有正文」成为顺序的必然结果。
★ 每图要有 `<title>`+`<desc>`，且 **desc／alt／图上可见文字／旁边正文 四者说同一件事**
  ⇒ **每画完一张回读一遍**（这一类**没有闸门能查**，而它已经出过三次真缺陷）。
```

## 二、写作要求（照旧）

```
· 面向**基础不好的初学者**：先直觉、再机制、最后代价。
· **减 AI 味**：不要「首先/其次/总而言之」，不要排比。禁词：随着、抓手、维度、生态。
  ★ 破折号「——」限额 1.0/千字（**全清最省事**）｜加粗限额 = 汉字数 ÷ 250
· **忠于源**：源里没有的推论不要写成源的结论；你补的在「溯源」逐条登记。
  ★ 凡写「原文说 / 讲义说」要能回源定位那一行。
  ★ **凡写「第 N 节」都要对一遍目录**；**凡写「第 N 讲」都要确认是仓内编号还是源编号。**
· **数字照录**并把源里每个数**都算一遍**；源自身矛盾就**照录 + 就地说明 + 登记**。
· 术语用 `[[term:xxx]]`（键只能 `[A-Za-z0-9_.-]`，**不能有空格**）。
  ★ **绝不写 `[[term:x]]（en，zh）` 或 `[[term:x]]（中文）`** ——
    模板两种情况下都会渲染 en 与 zh，所以那个括号**永远多余**，页面上会重复显示。
  ★ 加完术语**跑全仓**，有更早页面报漂移就**报我**，**不要改别人的页面**。
· 源里 `TODO` 或被划掉的节 ⇒ **照实登记那个空缺，不要代它补内容。**
```

## 三、图规范（房规，逐条硬约束）

```
R1 块间距 ≥25px ｜ R2 框高 = 字号×3 ｜ R3 框内文字光学居中（框 y + 框高/2 + 字号×0.35）
R4 画布边距 20–25px ｜ R5 不重叠、文字右缘+10px < 邻居左缘
R6 ★ 直线段只能沿轴；**斜的必须改成 C/Q 曲线**（不是「不能连不同行列」）
   ★ 曲线箭头方向由 **cp2 → 终点**：
       ↓ 下 cp2.x=end.x, cp2.y<end.y ｜ → 右 cp2.y=end.y, cp2.x<end.x
       ← 左 cp2.y=end.y, cp2.x>end.x ｜ ↑ 上 cp2.x=end.x, cp2.y>end.y
R7 调色板与字体栈：**照本课既有图的 `<svg>` 头抄**，别自创
★ **SVG 里的 `&` 写成 `&amp;`** ｜ **alt 里不要方括号** ｜ 垂直箭头对准某一格中心
★ **正文里不要混入兼容汉字**（如 `U+2F29`：渲染出来与小几乎一样，而 CJK 计数会漏掉它）

R8 ★★ **文字宽度要先估，再放**（`text-overflow` 那条红就是这么来的）：
     字号 10px ⇒ 拉丁 5.5px/字、CJK 10px/字 ｜ 字号 12px ⇒ 拉丁 7.0、CJK 12 ｜ 字号 16px ⇒ 拉丁 9、CJK 16
     · `text-anchor="middle"` ⇒ 左右缘 = x ± (字数 × 字宽)/2
     · **判据：文字右缘 + 10px < 右边邻居的左缘**（R5 那条）
     ⇒ ★ 而**我这一路真实踩过两次**：`dct-9` 的标题要 758.1px 而框只有 760px、
       `virt-9` 的要 844.5px 而框 760px ⇒ **两次都是标题太长**。
       ★ 所以**标题（16px）按「CJK 字宽 16px」估**：一行最多 ≈ 框宽 ÷ 16 个汉字（含标点）
       例：框宽 760 ⇒ **最多 47 个汉字**；而混合拉丁时按各自宽度加。
     ★★ **而这个估计对窄框偏乐观**（一位作者报的：4 列布局里框宽 ≈159px，
        而 `check_figures` 判 160px > 158.75px ⇒ **红**）——
        ⇒ ★ 原因是**每格的实际可用宽度比「框宽」小**（要扣掉左右内边距与相邻格间距）。
        ⇒ **所以每列窄于 ~180px 时，按「框宽 − 24px」再估**，或**直接减一列**（4 列改 2 行 2 列）。
R9 ★★ **箭头端点按固定公式取**（别目测）：**起点 = 源边 +5px，终点 = 目标边 −11px**
     （5px 间隙 + 6px 箭头尖伸出：`refX="2"` 而箭头长 8 ⇒ 尖伸出 6px）
     ⇒ 而**可见线段要 ≥6px**，否则箭头退化成一个点。
     ★ 粗线（`stroke-width` > 1.5）要用放大的箭头（12×12、`refX="3"`、终点 = 目标边 −14）
R10 ★★ **画布边距不对称时的修法**：把内容包进一个 `<g transform="translate(dx, dy)">`，
     **`dx = (右边距 − 左边距) / 2`**（dy 同理）
     ⇒ ★ 而**我这一路在这上面试错了两轮**（我把 pad 从 22 改成 64，而 64 高于 25px 上限 ⇒ 变成 warning）
       ⇒ **所以先算 dx，再一次改对**；负原点**无效**（那条判据用 width/height 属性）
R11 ★ **标题要对准「内容中心」而不是画布中心**（内容左右不对称时两者不同）：
     `内容中心 x = (最左元素左缘 + 最右元素右缘) / 2`
R12 ★ **虚线分组的样式在同一张图里要一致**：`stroke-dasharray="6,4"`、`rx` 8–12、
     `fill` `#f8fafc` 或 `none`、内边距 15–20px、组标题 11px（填 `#64748b`，放框内左上角 x+10/y+14）
     ⇒ ★ 而**组框的垂直定位要按「标题 + 内容」合起来算**，否则组框会偏心
R13 ★ **绘制顺序（SVG 没有 z-index，后画的在上面）**：
     ① 底层分组框/泳道 → ② 连线与箭头 → ③ 方框与文字
     ⇒ ★ 例外：**跨层回环线要在最后画**（否则会被方框盖住）
R14 ★ **若用脚本生成 SVG**：外部来源的文字**必须转义**再拼进去
     （`&`→`&amp;`、`<`→`&lt;`、`>`→`&gt;`、`"`→`&quot;`）
     ⇒ ★ 高危来源：团队名/需求描述/文件名（含 `&` 与 `<>`）
```

  ① 它没跑 ② 它跑了没报 ③ 它报了你没读到 ④ **你的测试自己造了个假情形**

★ **源是 HTML 时**：OCW 的「资源页」URL 返回的是 HTML 而不是 PDF；
  真 PDF 链接带 hash 前缀，要从资源页 HTML 里抽出来。

## 七、两条跨作者可复用的操作知识

### ① 大文件下载不能放在会被超时打断的**前台**调用里

```
· 一次是 curl 撞上工具的 120 秒上限被杀 ⇒ **文件根本没落盘**（Python 报 FileNotFoundError）
· 而另一次更隐蔽：**落了盘、curl 返回 0、却只有 614,400 字节且尾部没有 `%%EOF`**
⇒ **改用显式后台作业**，并仍然跑四道校验。
⇒ 而它与「接口说成功不代表结果可用」同型：`curl exit=0` 与「文件完整」是两件事。
```

### ② pip 用 **http** 代理，不要用 socks5

```
· `ALL_PROXY=socks5://127.0.0.1:7892` ⇒ pip 报
  **`Missing dependencies for SOCKS support`**（它需要 `PySocks`，而装 PySocks 又要先能装东西）
· 换成 **`HTTPS_PROXY=http://127.0.0.1:7892`** ⇒ 一次就成
★ 而它与 `curl` 不同：**curl 能直接走 `socks5h`，而 pip 不能** ——
  所以「同一个代理」对不同的工具**不通用**。
★ 实例：本项目的 `build_site.py` 要 `python -m mkdocs`，而 DSH 的 bundled runtime 里
  原本没有 mkdocs ⇒ **四门课的第六道门同时失效**，三位作者各报了一次同一处。
  修法就是那一条 pip 命令（装 `mkdocs` 与 `mkdocs-material`）。
```

### ③ 图文件名必须带本讲前缀

```
· 一位作者最初用 `lecture-map.svg`，而**第 11 讲已经有同名文件** ⇒
  `build_site` 直接报「同一 section 的配图是**平铺存放**的」⇒ 冲突。
· 他的处置是对的：**13 张全部改成 `<本讲前缀>-*.svg`**，并同步图内 id 与 markdown 引用。
⇒ 所以：**图名一律用 `content/` 目录名里的那个 slug 前缀**，别用 `fig-1.svg` 这种通用名。
```

### ④ 生成器的输出路径不能靠模块级常量隐式传递

```
· 一位作者把配图生成器的输出目录**写死**在上一讲的路径上
  ⇒ 13 张 `bfs-*.svg` 被写进了**上一讲**的 `figures/`。
· 他的处置**三步都对**，而第三步最难得：
  ① 只移走自己的文件（`newton-*` 一个字节没碰）
  ② **改生成器**（改成可传输出目录）—— 治根，而不只是清现场
  ③ ★ **去核 `git ls-tree HEAD`** 证明脏文件**没有进任何一次提交**
⇒ 而第三步正是本项目反复讲的那条：**「我做了修复」与「那个状态是干净的」是两件事**。
★ 而它与「大文件下载不能放前台」同型：**都是默认值悄悄决定了结果**。
```

### ⑤ 「点名不足」那条判据的三条机制（**作者实操踩出来的，而它们决定修法**）

```
① ★ **计数只看正文「尾巴以前」的部分**：`audit()` 在算点名之前会从
   `## 读完应该能回答 / 脉络回顾 / 溯源` 处**截断** ⇒
   **补在那些小节里的名字一个字都不算。**
② ★★ **计数数的是「命中的池条目」，而现在已按小写去重**（2026-09-29 第 109 轮修）：
   池是 `DEFAULT_SYSTEMS + 本课追加的`，而**同一个名字可能同时出现在两边** ⇒
   一个对象会被 append 两次 ⇒ 计数虚高。实测重复条数：
   cs168 **3**（HTTP/Linux/TCP）｜ mit-6.006 **1**（Python）｜ 其余 0。
   ⇒ 所以**现在一个名字只算一条**（而去重暴露了 10 页真欠账）。
③ ★★ **池是按课分的** ⇒ 给 cs168 补 `ASIC`/`x86`/`ARM`（它们在别的课的池里）
   **纹丝不动**。⇒ **只用报错信息里给出的那个池**
   （报错行会写「本课在 course.toml 里登记的池里有：…」）。
★ 外加一条：**补池内名字可能触发 `validate` 的术语漂移警告**
  （一位作者踩了 `ISP`/`RFC`/`RPC` 三次）⇒
  若那个名字**是 glossary 词条**，要么补 `[[term:x]]` 标记，要么换个说法。
  ★★ 而**加词条之前先 grep 全仓**：若那个词的英文原词在**已提交的页面**里已出现，
    登记它会给那些页面添漂移警告 ⇒ **那就别登记**（一位作者因此没登记 `DNS`，改用全称）。
```

### ⑥ 漂移判据是**全页级**的，不是按段的（我读过 `validate.py`）

```
· `used` 是**全页级**的集合（在段落循环**之前**就收集好了所有 `[[term:…]]` 标记）
· 而漂移判据是 `if key in used: continue` ⇒ **所以「标记一次就够」是对的**
⇒ ★★ 也就是：**只要这一页的**任何地方**标记过那个词，整页都不会再报它的漂移** ——
  **不需要让标记与英文原文同段。**
★ 而一位作者误以为「判据是按段看的」，于是**换掉了两条源文引文**
  （只因为它们含 `router`/`routing`）—— 而那个代价**本来不必付**
  （引文是源材料，不该为一条判据被换）。
⇒ 所以遇到漂移警告：**在该页任何一处自然地标记一次**即可，
  **不要去动引文，也不要改判据**。
```

## 源材料问题的四种子形态（**每一种都有一位执行者踩出来过**）

★ **四种都不需要读懂整段** —— 它们只需**把两处字面对一眼**（或拿一条已有判据套一下）。
⇒ 所以它们**都能写成可执行的动作**，而**每一种都该在报告里给覆盖面**（核了哪几处）。

### ① 变量名对了，而**方向/动词**错了
```
实例：mit-6.006 #16 的 `while Q = φ`（应为「当 Q 不为空」）
      mit-6.006 #21 的 `c(i, j) = maximum of`（而编辑距离是找**最小**代价）
检查：**专门核方向词** —— 最大/最小、增/减、前/后、包含/被包含。
来源：mit6006-author 在 #16 与 #21 各抓到一处。
★ 而它在 #22 按这条定向核了一遍并回报：「本讲四处方向词（指法 min / 俄罗斯方块 max /
  马里奥 max / 背包 max），四处都与语义一致，没有第二处 max 型笔误」
⇒ **那个「覆盖面 + 结论」的形态是可验证的**（我也能去数那四处）。
```

### ② **等号两边是同一串**
```
实例：cs168 #33 的
      "From: S, Port 80, To: R1, Port 60000" must be rewritten as "From: S, Port 80, To: R1, Port 60000"
      —— 一句「**A 必须改写成 A**」在字面上就是空的。
检查：**照录等式时先看两边是不是一样**（一个**字面**检查，不需要理解语义）。
来源：cs168 的作者在 #33 抓到。
```

### ③ **说 N 项而列了 M 项**
```
实例：cs168 #26 的 `three parts: method, URL, version, and optional content`（**说三部分、列了四项**）
      mlsys `llm-finetuning-4` 的标题「提示工程的**三个**局限」，而 desc／alt／正文都写两条
检查：**凡写「N 个…」就数一遍后面跟了几项**。
★ 而**反向也要注意**：若源文列了 M 项而**你没给它编号** ⇒ 那就不产生 N/M 不一致
  （mit6006-author 在 #23 对「NP 完全清单 9 条」与 #24 对「坐垫 Top 10」都是这么处理的）。
```

### ④ ★ **源文举的例子不合源文自己教过的判据**
```
实例：cs168 #35 —— 源文举例的路由器 MAC `01:ab:cd:ef:42:01`，**首字节最低位是 1**，
      而按**本课第 29 讲讲过的判据**那是**组地址**的形态（而它是个路由器）。
检查：**凡源文举地址／MAC／端口／编号／复杂度这类例子，用手边已有的判据核一遍它。**
来源：cs168 的作者在 #35 抓到。
★★★ 而它的形态与前三不同：前三都是「把两处字面对一眼」，
   而 ④ 是「**把一条已写进页面的判据反向用在源材料上**」。
★ 而它**特别有效**，因为**源文自己教过那条判据** ⇒
  所以「它的例子不合它的判据」是一个**它自己会承认的矛盾**，而不是我们的偏好。
```

### ★★ 而 ④ 可以系统化
```
**每当一讲教了一条「可判定的判据」，就该拿它去核源文那一讲的全部例子。**
· 可判定的判据包括：地址类型（单机/组播、子网地址/主机地址）、端口范围（熟知/注册/动态）、
  复杂度上下界（Θ/Ω/O 的方向）、量级关系（谁在谁的哪一侧）、计数（说 N 项）
⇒ 而那是一个**可以写进派单的通用动作**（比「注意核对」具体得多）。
```

### ★★★ 与「抽取层畸变」的区别（**别把它们混起来**）
```
· **四种子形态**：责任方是**源**（源文自己写错了/举例不合判据）
· **抽取层畸变**：责任方是**仪器**（文本抽取把 `≠` 显示成 `=`）
  ⇒ 判据：**同一个畸变在两个引擎上一致、且落在逻辑上唯一的位置时，责任方是仪器而不是源**
  ⇒ 实例：mit-6.006 已命中三次（#16 `while Q = φ`、#23 两处条件句、#24 迁移递推两分支）
★ 而**这两类的处置不同**：
  · 源的问题 ⇒ **预告 → 照录 → 更正 + 登记**
  · 仪器的问题 ⇒ **照录所见的文本 + 给出逻辑上唯一的读法 + 登记「不断言源印错」**
```

### ★ 处置的统一形态（三种落点，而不只是「发现了矛盾」）
```
① **是矛盾** ⇒ 预告 → 照录 → 更正 + 登记
② **不是矛盾（核过了）** ⇒ **也登记**（写成「核过但不是矛盾的」）——
   ★ 因为**若不登记，下一个人会重新怀疑它一次**
   （cs168 #32 的作者对「Offer 例子只列三个而 §1 列四样」就是这么处理的）
③ **核不到** ⇒ 说明核不到在哪（并写清**你没做的事**）
```
