# MIT 6.824 第 3 讲（GFS）· 陌生读者测试题

来源：https://pdos.csail.mit.edu/6.824/notes/l-gfs.txt（2026-09-28）

1. GFS 被设计成"为了性能与简单性而牺牲一致性"，请说明它假定的应用场景与负载特性是什么，以及为什么在这样的前提下这类取舍是可以被接受的。
2. GFS 整个集群只有一个 coordinator（主节点），却要面对成百上千个客户端。请解释它的职责是如何划分的，以致客户端在读写数据时为什么不需要让 coordinator 经手数据本身。
3. GFS 把 chunk 的大小定得远大于一般文件系统的块大小。请解释为什么采用这么大的 chunk，以及这一选择如何影响客户端与 coordinator 之间的交互次数与协调开销。
4. 当 coordinator 长时间联系不上某个 chunkserver 时，它是否应该立刻把该机器上的所有 chunk 重新复制到别处？请说明过早开始复制和过晚开始复制各自要付出什么代价；当一个曾经失联的 chunkserver 重新上线并上报自己保存的内容时，coordinator 又依靠什么判断它手里的副本是否已经过期？
5. GFS 的一致性模型用 defined、consistent、inconsistent 三种结果来描述写入的效果。请说明每一种结果对应的是怎样的写入情形；并解释为什么在完全没有发生任何故障的情况下，两次并发的写入仍然可能导致某些数据丢失，以及 record append 是如何改变这一结果的。
6. 请完整描述一次写操作中客户端、主副本和次副本之间的步骤，并解释为什么客户端要先把数据推送给所有副本、最后才向主副本发出写请求，主副本在这条流程中所起的核心作用是什么。
7. 从系统的长期演化来看，当集群中的文件数量增长到远超设计预期时，单一 coordinator 会成为瓶颈。请说明哪些具体的操作或数据结构会变得昂贵，并指出 GFS 在 coordinator 故障切换方面曾经存在的代价。
