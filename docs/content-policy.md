# 内容策略 · Content Policy

> **必读。** 这份文档的作用是让项目不侵权。授权风险是本项目最大的敌人，比翻译质量更能决定生死。

## 核心原则

**我们发布的是自己写的讲解，不是别人课程的复制品。**

这一条不是道德姿态，而是法律结论：

- **思想与概念不受著作权保护**，表达才受保护。
- 因此「我们自己写一篇讲解同样概念的原创文章」风险最低。
- 而「翻译完整逐字稿」或「翻译视频字幕」属于**衍生作品**，它复制了原作的全部表达 —— 风险完全取决于原课程的实际许可条款。

这直接决定了产品的默认形态：**讲解为主，翻译为辅**。
（**在 6.824 上，翻译这一侧目前已完全关闭** —— 讲义无许可声明，见下。）

### ⚠️ 核实授权时的两个方法论坑（我们踩过，各一次）

**坑一：必须抓原始 HTML，不能只看过滤掉标签后的纯文本。**
6.824 **主页**的许可写在页脚的**图片徽章**里：

```html
<a rel="license" href="https://creativecommons.org/licenses/by/3.0/us/">
  <img alt="Creative Commons License" src="...">
</a>
```

把标签过滤掉再搜 "license" / "copyright"，这个页面会**命中 0 次**，
于是得出「未声明许可 = 保留所有权利」的**错误结论**。我们就是这样错了一次。

**坑二（2026-09-28 二次核实新增）：找到徽章之后，还必须确认它覆盖哪份文件。**
我们纠正坑一之后，**又立刻犯了坑二** —— 由「主页有徽章」推出「讲义可以翻译」。
二次核实补查了**我们实际依据的讲义文件** `notes/l01.txt`：
`rel="license"` / CC 链接 / 版权声明 **均为 0** ⇒ **讲义授权 `未确认`**。

> **规则：核实的对象必须包含「我们实际要用的那份文件」，而不是课程入口页。**
> 拿不到该文件的许可依据 ⇒ 按 `未确认` 处理 ⇒ **该材料的逐字稿与双语原文对照一律不产出。**

### ⚠️ ShareAlike 的传染边界（这是架构约束，不是偏好）

MIT OCW 与 Composing Programs 是 **CC BY-NC-SA 4.0**，其中 **SA（相同方式共享）是传染性条款**：
只要我们的产出改编自它们，该产出**必须**同样以 CC BY-NC-SA 4.0 发布 —— 于是它也不能商用。

而 MIT 6.824 / 6.1810 的**已取证页面**是 **CC BY 3.0 US**：许可文本没有 SA，**不传染**。
⚠️ **但「可商用」这个推论不能直接下**（2026-09-28 二次核实修正）：
6.824 的徽章**只在主页**，而讲义 `notes/l01.txt` 无任何声明 ⇒ 讲义 **`未确认`**，
「无 NC 所以可商用」只在**许可确实覆盖该材料时**成立。
**现行结论：6.824 只发布原创讲解（`explanation`）；不产出逐字稿，不做双语原文对照。**

**两类内容不能在同一个授权边界里混合：**

| 来源 | 授权 | 商用 | Copyleft |
| --- | --- | --- | --- |
| MIT 6.824 / 6.1810（已取证页面） | CC BY 3.0 US（6.824 仅主页） | ⚠️ 就**已覆盖材料**而言为 ✅；讲义 `未确认` | ❌ 无 |
| MIT 6.824 讲义 `notes/*.txt` | **无声明 → `未确认`（默认保留所有权利）** | ⚠️ 未确认 | — |
| MIT OCW / Composing Programs | CC BY-NC-SA 4.0 | ❌ | ✅ 传染 |

落实方式：

- **一课程一仓库**（模板已经是这个设计），授权边界天然按仓库隔开。
- **不要把 OCW / 教材材料混进 6.824 的仓库。**
- 若某个仓库确实要同时使用两类材料，**必须**单独建一个 BY-NC-SA 子树，
  并在该目录显式声明许可，否则一次混用会把整个仓库拖成「非商业」。

这也是为什么「内容与工具分离、一课程一仓库」不是洁癖 —— 它是**授权上的必要设计**。

### 以下内容一律不产出

- 完整讲座逐字稿的翻译
- 视频字幕的翻译
- 官方作业 / Lab 题面与答案的翻译
- 原始课件（PDF / PPT / 视频）的转载

> 这一节是**硬规则**。**6.824 现在明确落在此列**：其讲义无许可声明 ⇒ `未确认`，
> 因此**只有原创讲解（`explanation`）会被发布**。
>
> 与之配套的**双语「原文对照」排版**（本质是逐字稿的并排呈现）走**同一道闸门**：
> 只有 `[license.materials].notes = true`（即该类材料的授权已核实为允许）时才会注入。
> 6.824 的 `materials` 全为 `false`，所以**不注入**。代码侧双保险：
> `validate.py` 对 `output_mode = "transcript"` **退出码 1 拒绝**；
> `build_site.py` **不注入**原文对照块。

## 我们自己的授权，与「拒绝执行」

### 我们的产出用最宽松的协议

| 对象 | 协议 |
| --- | --- |
| 代码 | **MIT** |
| 原创内容（讲解、导读、术语表、配图） | **CC BY 4.0**（允许商用与改编，只需署名） |

### ★ 但课程规定优先 —— 这是硬规则

上面的宽松协议只覆盖**我们自己原创的部分**。课程或论文的条款更严格时，**以它为准**：

| 课程条款 | 我们的分类 | 我们怎么做 |
| --- | --- | --- |
| **明确开放许可**（CC BY 类，如 MIT 6.824 / 6.858 的主页） | `allowed` | 就**已覆盖的材料**而言，产出可用 CC BY 4.0，**必须保留上游署名**。⚠️ **范围限定**：徽章只在主页、子页面无声明时，该子页面按 `未确认` 处理 |
| **CC BY-NC-SA 类**（MIT OCW、Composing Programs、Full Stack Open） | `allowed`（带约束） | 产出**必须**同样以 CC BY-NC-SA 发布，且**不得商用**；SA 会传染 |
| **未声明许可**（没有任何许可或版权措辞，如 6.824 / 6.1810 的讲义文件、CMU 15-445） | `unknown` | **只发布我们自己独立撰写的讲解**，不复制其表达；**逐字稿与双语原文对照不产出** |
| **明确保留所有权利 / 明确声明版权**（如 UC Berkeley CS 61A 的 `Copyright ©2026, Regents of the University of California`） | `forbidden` | ⛔ **拒绝执行**：不为该课程建站，不产出任何内容 |

**`unknown` 与 `forbidden` 必须分开，这是本文件最容易搞错的一处：**

- **未声明**≠**禁止**。没人声明过，我们不知道，所以**不敢转载**；但讲思想不侵犯表达，
  因此原创讲解可以做。6.824 走的就是这条路。
- **明确声明版权**则是权利人表了态。用户给的方针是「课程不允许传播，那就明确拒绝工程请求」——
  我们照办，**直接不做**，而不是「只做讲解」。这样也不会让人误以为我们在蹭一门明确不开放的课。

落到字段上：`redistribution = "unknown"` 仍可构建（只是锁死 `explanation`），
`redistribution = "forbidden"` 会让 `validate.py` 以**退出码 3**拒绝执行。

### ⛔ 拒绝执行是怎么落地的

在 `course.toml` 写：

```toml
[license]
redistribution = "forbidden"      # 课程明确不允许传播
evidence_url = "https://.../terms"  # 依据
```

于是：

- `validate.py` → **退出码 3**，打印明确理由，不再跑其余校验；
- `build.py` → **退出码 3**，不产出任何站点；
- CI 里 `build` 依赖 `validate` → **部署不会发生**。

论文同理，写在 `papers.toml` 的 `[paper.license].redistribution`。

**为什么用独立的退出码 3**：让人一眼区分「内容写错了」（1，改改就好）与
「这件事我们不做」（3，改内容没用）。

**为什么连原创讲解也拦**：法律上，我们独立撰写的概念讲解并不复制对方表达，通常是安全的。
但课程既然明确说了不要传播，本项目**选择不做** —— 这是**政策性选择**，比法律底线更保守，
也正是「以课程为准」的字面执行。

如果将来授权状况变了，改 `redistribution` 并附上 `evidence_url` 即可，**不需要改任何代码**。

## 内容分级

> 下表是**一般著作权推理**（ideas vs. expression），**不是**已核实的许可条款。最终以各课程实际条款为准。

| 做法 | 风险 | 说明 |
| --- | --- | --- |
| 自己撰写讲解，讲同一批概念 | 🟢 最低 | 概念不受保护。但须避免逐句改写原文、避免复制原图 |
| 链接官方来源 + 自己的解读与署名 | 🟢 低 | 署名是伦理规范，**但它本身不能豁免侵权** |
| 翻译完整讲座逐字稿 | 🟡 高 | 衍生作品，复制全部表达；须有明确许可 |
| 翻译视频字幕 | 🟡 高 | 同上，且叠加视频平台条款 |
| 转载原始课件 / 视频 | 🔴 最高 | 即使许可宽松，视频还另有平台条款；**一律链接，不转载** |
| 翻译官方作业答案 | 🔴 最高 | 著作权 + 学术诚信双重风险；且答案常被故意不公开 —— 默认无授权 |

## 署名与标注规范

任何涉及具体课程的产出，文件头部**必须**包含：

```markdown
> 来源课程：MIT 6.5840 / 6.824 Distributed Systems
> 对应内容：Lecture 3 — Primary-Backup Replication
> 官方链接：https://pdos.csail.mit.edu/6.824/
> 授权依据：<已核实条款 / 待核实 —— 未核实不得发布>
> 本文为 CourseLingo 原创讲解，非官方材料，与原课程方无隶属关系。
```

页面与仓库层面还须显著标注：

- 「非官方 · 社区项目」
- 不得使用任何学校校徽、课程 Logo
- 不得暗示官方背书或合作关系

## 下线机制

任何仓库中的内容，一旦被指出超出授权范围：

1. **立即下线**（不回退讨论、不等核实结论）。
2. 在对应仓库开 issue 记录决策。
3. 复盘该课程的授权判断是否有系统性偏差。

宁可错杀，不可拖延。

## 逐课程复核清单

每门课程在开工前，必须书面确认以下各项：

- [ ] 讲座笔记 / 幻灯片 的许可条款
- [ ] **我们实际依据的那份文件本身**（如 `notes/l01.txt`）是否带声明或版权行
      —— **只核课程入口页不够**：6.824 主页有徽章、讲义无声明，就是这一条漏掉的结果
- [ ] 声明/徽章的**覆盖范围**是否明确列出所覆盖的材料（徽章只是链到通用许可文本时，覆盖范围未确立）
- [ ] 讲座视频 的许可条款（注意与课件可能不同）
- [ ] 作业 / Lab 题面与答案 的许可条款
- [ ] 教材（如有）的许可条款
- [ ] 课程页是否有明确的 reuse / citation 声明
- [ ] 是否允许**商业**使用
- [ ] 是否允许**衍生作品**（翻译即为衍生作品）
- [ ] 是否有 **ShareAlike**（相同方式共享）要求，是否会传染到我们的产出
- [ ] 署名要求的具体形式

## 兜底原则

**条款未核实 = 不发布。**

若某课程确实需要翻译逐字稿或字幕，正确路径是**先写信取得授权** —— 联系课程讲师或相应版权办公室，而不是先发布再说。
