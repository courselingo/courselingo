# course-explain · 让讲解真的讲懂

`course-translate` 负责「合规地产出这一讲」；**本 skill 负责「这一讲到底有没有讲懂」**。

## 先立一条纪律：讲解 ≠ 翻译

**翻译**是「把英文句子换成中文句子」，读者仍需自己补背景、补推导、补上下文。
**讲解**是「让不看英文原文的读者读懂这一讲」。

判据（写作时随时自问）：

| 自问 | 如果是「是」→ |
| --- | --- |
| 这句话是不是英文句子的逐句对应？ | 重写：先想清楚要说什么，再用中文说 |
| 读者需要原文里没有的背景才能懂吗？ | **补上**（概念前置） |
| 这里的推导是不是跳了关键一步？ | **补上中间过程** |
| 这段代码读者能看懂「为什么这么写」吗？ | **加中文注释** |
| 读者知道这段话对应原文哪里吗？ | **加溯源位置** |
| 这一句去掉之后，读者会不会更懂？ | 删掉。别凑字数 |

**为避免逐句改写**：写作时**不要**逐句盯着原文写。先读完整小节，合上原文，用中文把逻辑重讲一遍；再回头核对有没有漏掉概念。

## 一、概念前置

**定义**：读者**需要**、但原文**默认已经知道**的背景。它是「原文读者是本校学生、我们的读者不是」这个差距的补丁。

做法：
1. 通读本讲，列出原文**直接开始使用**、却没在本讲解释的概念。
2. 对每个概念问：读者不知道它，会不会卡住？会 → 写 2–5 句前置。
3. 前置放在**用到它之前**，不要堆在文章开头当背景墙。
4. 前置里出现的术语同样要走 `[[term:key]]` 标记。
5. 前置**只补必需**：补到「能读懂本讲」为止，不要顺手写一篇教材（那会变成重写课程 —— 架构文档里明确列为未解决问题）。

**检查方式**：找出一段「直接开始用某个未解释概念」的地方。存在即 fail。

**反例**：
> 主节点把日志复制到从节点。

（读者不知道「日志」在这里指什么、为什么需要它。）

**正例**：
> 主节点把日志复制到从节点。这里说的日志（log）不是运维意义上的日志文件，而是一串**有序的操作记录**：
> 每个副本按同一顺序执行同一串操作，就会得到同一个状态。复制日志，本质上就是复制状态。

## 二、推导可见

**定义**：不跳步。关键推导有中间过程，每个结论都能追溯到上一步。

做法：
1. 全文搜这些词：**因此 / 所以 / 显然 / 可得 / 易知 / 由上式 / 于是**。
2. 逐个回溯：上一步到这一步之间，缺了什么代数变形 / 逻辑步骤 / 前提假设？
3. 缺就补上。**「显然」是两个字的谎话** —— 在 CS 课程里，被标成「显然」的地方往往正是难点。
4. 涉及公式的推导：把符号的**含义**写清楚（每个变量是什么、单位/取值范围），别默认读者记得。
5. 涉及算法/协议：把状态、动作、可能失败的情形按顺序摆出来，别用一句「然后进行选举」带过。

**检查方式**：每个「因此 / 显然 / 可得」处都必须能指回上一步。指不回去即 fail。

**模板**：
```markdown
设 …（符号含义：…）
第一步：…（理由：…）
第二步：…（理由：…）
所以 …（这就是上面两步合起来的结果）
```

## 三、代码走查（代码有注释）

**定义**：代码块的关键行有**中文注释**，解释的是**为什么**，不是把代码翻译成中文。

做法：
1. **单块代码保持短小（≤ 400 字符）** —— 这是**可读性**要求：一段代码超过一屏，读者还没看到解释就迷路了。
   （当前 `validate.py` 的转载探测会**跳过围栏代码块**，所以代码块本身不会被这条拦住；但**代码块之外的成段英文散文会被拦**。详见 `docs/SOP.md` §14-6。）
2. 超长就**拆分**：按逻辑阶段切成 2–3 块，每块前面用正文文字说明这一段在干什么。
3. 注释写**意图与原因**：
   - ✅ `// 加锁后再检查任期，否则可能在检查与写入之间被别人抢走领导权`
   - ❌ `// 加锁` / `// 检查任期`
4. **不要整块照抄**源材料的代码。学生作业代码与官方答案属于禁止转载的内容（答案翻译**永久排除**）。
5. 伪代码优先：如果只是为了讲清协议，用伪代码 + 注释比贴真实代码更能讲懂，也更安全。

**模板**：
````markdown
先看第一步：判断自己是不是最新的领导者。

```go
if args.Term < rf.currentTerm {   // 对方任期更旧，说明自己已经过期，直接拒绝
    return false
}
```

这一步的用意是 …
````

## 四、什么时候需要配图（交给 `course-diagram`）

**图是讲懂的工具，不是装饰。** 判断标准：**这段内容的难点是不是「关系 / 时序 / 结构」，而不是「文字本身」？**

| 需要图 | 不需要图 |
| --- | --- |
| 时序与消息传递（RPC 顺序、超时、选举回合） | 纯文字定义与术语解释 |
| 状态机与状态迁移（副本状态、生命周期） | 单行公式推导 |
| 多方并发与交错（两个节点同时竞选） | 一段直白代码 |
| 系统结构 / 分层 / 数据流 | 罗列性的清单 |
| 「为什么这样设计」需要对比两种方案 | 结论性总结 |

流程：
1. 写作时**先标记**要图的位置（占位注释即可），把「这一节要表达什么关系」写清楚。
2. 交给 `course-diagram` skill 生成 SVG。
3. 存到 `content/<NN>-<slug>/figures/`，命名建议 `<slug>-<n>.svg`。
4. 正文用 `![<中文说明>](figures/xxx.svg)` 引用，**alt 文本必须写**（可访问性 + 图挂掉时的兜底）。
5. 图**必须自己画**：不得复制或改写原课程的幻灯片、图表、示意图（授权风险最高的一类行为）。

> spec 只规定 Markdown 支持图片、目录为 `figures/*.svg`；SVG 尺寸 / 命名 / 是否内联未定义（见 `docs/SOP.md` §14-9），按上面的约定执行。

## 五、可溯源

每讲结尾给出对应原文位置：

```markdown
## 溯源

- 对应：MIT 6.5840 / 6.824 Lecture 3 — Primary-Backup Replication
- 位置：讲座笔记 l03.txt 第 1 节；视频 00:12:30–00:26:10
- 官方链接：https://pdos.csail.mit.edu/6.824/
```

- 给**位置**（讲座号 / 时间戳 / 页码 / 章节名），**不给文本**。
- 署名是伦理规范，**但它不能豁免侵权** —— 该补的授权仍然要补。

## 六、语气（brand.md）

| 要 | 不要 |
| --- | --- |
| 像助教：直接讲清楚 | 像营销号：铺垫、煽情 |
| 承认复杂：拆开讲 | 粉饰成「其实很简单」 |
| 如实写进度、局限、授权边界 | 吹牛、用「全网最全 / 颠覆 / 封神」 |
| 面向读者写「你」 | 「用户」「学员」自称读者 |
| 中英并用有纪律：术语首次「中文（English）」，之后统一用中文 | 中英混排无规律 |

## 七、篇幅控制

**一讲 = 一次课（或一个小节）。**

- 读者应当在一次阅读里读完并理解。
- 超长 → **拆成两讲**，各自有独立的 `lecture` 与 `slug`，然后重跑 `validate.py`（`lecture` 必须重新编号且保持唯一）。
- 判断方法：如果一讲里有三个以上互不依赖的主题，它其实是三讲。
- 不要把整章教材塞进一讲。架构文档把「讲多深算讲懂而不算重写课程」列为**未解决的问题** —— 所以遇到边界时，宁浅而完整，不要深而失控。

## 交付前自检（把每一项都能指到具体位置）

- [ ] **概念前置**：列出的每个「默认已知」概念都已补，且补在用到它之前
- [ ] **推导可见**：每个「因此 / 显然 / 可得」都能指回上一步；公式符号已定义
- [ ] **代码有注释**：每个代码块关键行有**中文**注释，讲的是「为什么」；代码块保持短小
- [ ] **可溯源**：结尾有讲座号 / 时间戳 / 页码
- [ ] **术语一致**：同一概念全篇同一中文词；术语都打了 `[[term:key]]`
- [ ] **配图**：该有图的关系型内容都有图；图是自己画的；alt 文本已写
- [ ] **语气**：像助教；用「你」；无禁用词
- [ ] **篇幅**：一次课的量，主题收敛
- [ ] **反翻译自检**：抽 3 段自问「这是我们写的，还是原文的改写？」有疑虑就重写

## 不要做

- ❌ 逐句翻译或逐句改写原文（换同义词不算自己写）
- ❌ 用「显然」「易知」掩盖跳步
- ❌ 注释写「加锁」这种对代码的字面复述
- ❌ 整块照抄源材料代码，或翻译官方作业 / Lab 答案
- ❌ 复制原课程幻灯片或图表
- ❌ 为了显得完整而写与讲懂无关的段落
